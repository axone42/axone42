# 상담 흐름 개선 기록

2026-09-07. 대표 프로젝트 제작·심화는 이번 작업에서 제외했다.

## 선택 정보 유지

- 서비스 상세의 두 가격 링크가 서비스 ID와 가격 항목을 함께 전달한다. 같은 가격 항목을 사용하는 바이브코딩·AI 자동화 교육도 구분한다.
- 가격 계산기는 URL의 항목을 읽고, 선택 변경을 URL에 반영한다. 새로고침과 뒤로가기에 대응하며 선택 해제한 서비스가 다시 추가되지 않도록 한다.
- 프로젝트 상세, 데모 상단·하단의 문의 링크는 프로젝트 ID를 전달한다. 문의 화면에서 프로젝트를 확인·해제할 수 있다.
- 접수 API는 전달된 ID를 내부 프로젝트 목록과 대조해 제목을 정한다. 서버에서 확인한 프로젝트 제목을 DB와 알림에 기록한다. 입력한 문의 내용은 자동 문구로 덮어쓰지 않는다.

## 납품·운영 안내

서비스별 산출물 예시와 공통 합의 항목을 서비스 상세 12개에 추가했다. 전체 서비스와 가격 페이지에도 결과물·완료 기준, 인수인계·권한, 수정·운영 지원을 설명한다. 확정되지 않은 납품 수량·무상 수정 기간·지원 시간은 임의로 약속하지 않는다.

## 홈페이지와 README

홈은 업무 선택 → 기존 데모 → 기술 스택 순서로 배치한다. 기존 마퀴의 디자인과 동작을 유지했다. README는 체험 준비 중인 3개 프로젝트의 Live 표기를 수정하고 실제 사이트 의존성과 도입 검토 기술을 구분한다. 회사 소개와 푸터에서 코드·기술 설명으로 연결한다.

## 전환 이벤트

| 이벤트 | 발생 시점 |
|---|---|
| service_select / service_deselect | 홈 목적·서비스 상세 선택 또는 가격·문의의 항목 선택 변경 |
| demo_view | 데모 경로 진입 |
| demo_interaction | 데모 화면에서 첫 버튼 클릭 또는 입력 변경. 실제 AI 처리 완료와 구분 |
| contact_click | 사이트에서 상담 링크 클릭 |
| contact_start | 문의 양식 첫 입력 변경 |
| contact_submit | 필수 입력 검증을 통과해 API 제출 |
| contact_error | 입력 오류, 서버 실패 또는 네트워크 실패 |
| generate_lead | API가 DB 저장 완료를 확인한 뒤 성공 응답. 재시도 실패와 허니팟 응답은 제외 |
| email_draft / email_click | 메일 앱으로 보낼 내용 정리 / 메일 앱 열기. 실제 발송·접수 완료로 집계하지 않음 |

이벤트에는 페이지 경로와 정해진 식별자만 포함한다. 이름·이메일·전화·문의 본문·접수번호·URL 쿼리는 전송하지 않는다. GA4 광고 개인화·Google Signals와 자동 page_view 전송을 끄고 경로 변경을 직접 측정한다.

상담 이벤트의 `service_id`는 전달받은 구체적인 서비스 ID, 단일 가격 항목 ID, `multiple`(여러 항목), `undecided`(미정)로 구분한다. 여러 서비스를 선택했다고 접수 완료를 여러 번 집계하지 않는다.

### GA4 연결

1. GA4의 웹 데이터 스트림에서 측정 ID(`G-...`)를 확인한다.
2. Vercel 프로젝트의 Production 환경 변수 `NEXT_PUBLIC_GA_ID`에 설정한 뒤 다시 배포한다. 빌드 시 적용되는 공개 식별자다.
3. GA4 웹 스트림의 **향상된 측정**을 끈다. 페이지 조회·폼 제출의 중복 측정과 문의 URL 쿼리 수집을 방지하고 이 사이트의 명시적 이벤트를 사용한다.
4. 실시간 보고서·DebugView에서 이벤트를 확인하고 `generate_lead`를 주요 이벤트로 지정한다. `service_id`, `project_id`, `source`, `reason`이 필요하면 이벤트 범위 맞춤 측정기준으로 등록한다.
5. 서비스별 상담 시작·접수 완료 추이를 확인한다. 데모 조작은 실행·처리 성공의 증거가 아니며, 이벤트 수를 고유 고객 수나 계약 건수로 해석하지 않는다.

측정 ID가 없으면 Google 스크립트를 불러오거나 외부 분석 서비스에 전송하지 않는다. 내부 브라우저 이벤트 `axone:conversion`으로 연결 전 검증이 가능하다. ID 연결 전 기간의 데이터는 소급 수집되지 않는다.

### 상담 접수 운영 설정

상담은 Neon PostgreSQL에 먼저 저장하며 Mailgun 설정이 없어도 접수할 수 있다. Slack 알림 실패도 접수 성공을 취소하지 않는다. 관리자 접수함, Slack 재전송, Gmail 수신 연동 설정은 [상담 운영 안내](inquiry-operations.md)에 기록한다. Gmail 메일함과 Slack 수신 채널은 계정 연결 후 활성화한다.

공식 참고: [GA4 이벤트 설정](https://developers.google.com/analytics/devguides/collection/ga4/events), [generate_lead](https://developers.google.com/analytics/devguides/collection/ga4/reference/events#generate_lead).

## 검증 방법

`npm test`로 선택 정보·금액 계산·문의 API를 검사한다. 메일 제공자는 테스트 대역을 사용한다. 브라우저에서는 서비스→가격→문의, 프로젝트→문의, 선택 변경·해제·새로고침·뒤로가기, 성공·실패별 전환 이벤트, 모바일 화면을 확인한다. 메일·Slack 알림은 테스트 대역으로 확인한다. DB 저장 검증용 문의는 실행별 식별자로 생성하고 검증 후 해당 건만 삭제한다.

이전 상담 흐름 검증 결과(DB 접수 전): 자동 검사 9개, TypeScript 검사와 프로덕션 빌드 통과. 공개 페이지 40개의 SEO·내부 링크 검사 오류 없음. 주요 화면 7개를 1440·768·390·360px에서 확인했다. 서버 접수 모드의 성공·실패는 브라우저 요청 대역으로 검증했고, 메일 미설정 모드에서는 초안 내용·수정 후 재작성·프로젝트 해제·접수 성공 오집계 방지를 확인했다.
